# Agent模拟引擎说明

## 一、模拟引擎架构定位（建议配图1：三层架构图）

模拟引擎（TradingSimulator）是系统的核心控制层，位于Agent-Tool-Simulator三层架构的最底层，负责整个交易模拟过程的时间推进和状态管理。模拟引擎作为Agent与市场数据之间的桥梁，通过严格的时间控制确保Agent只能访问当前日期及之前的历史数据，从而保证模拟测试的公平性和真实性。模拟引擎管理投资组合状态、更新持仓价格、记录每日快照，并最终生成完整的性能报告，是整个系统的"时间守护者"和"状态管理者"。**交易执行由工具层（TradingTools）负责**，当Agent调用`buy_stock`或`sell_stock`工具时，工具层会验证交易请求并直接执行交易操作、更新账户状态，模拟引擎不参与交易执行过程。

## 二、核心功能模块（建议配图2：功能模块图）

模拟引擎包含五大核心功能模块，每个模块都有明确的职责分工。

### 1. 时间循环控制模块

时间循环控制模块负责获取交易日列表并逐日推进模拟过程，确保每个交易日都按照标准流程执行，是整个模拟引擎的"时间守护者"。

**要点：**
- 从数据库获取指定时间范围内的所有交易日列表
- 自动过滤非交易日（周末、节假日）
- 严格按照交易日顺序逐日推进，确保时间单向推进且不可回溯
- 控制整个模拟流程的开始、进行和结束

### 2. 持仓价格更新模块

持仓价格更新模块在每个交易日开始时自动更新所有持仓股票的当前价格，使账户市值反映真实市场状态，确保Agent看到的账户信息准确无误。

**要点：**
- 在每个交易日开始时执行价格更新
- 遍历所有持仓股票，获取当日收盘价
- 更新Portfolio中每个持仓的current_price
- 更新Portfolio的current_date为当前交易日
- 使账户市值（market_value）反映真实市场状态

### 3. Agent决策调用模块

Agent决策调用模块将当前账户状态（资金、持仓、收益率）传递给Agent，触发其决策流程，是Agent与模拟引擎交互的桥梁。

**要点：**
- 准备账户信息摘要（现金、市值、总资产、收益率）
- 准备持仓明细信息（每只股票的持仓数量、成本价、当前价、盈亏率）
- 调用Agent的make_decision方法，传入当前日期、账户信息和工具集
- 接收Agent返回的决策结果（包含success、analysis、reasoning等字段）
- 处理Agent决策异常，确保模拟过程不会因决策失败而中断
- **注意**：Agent通过工具层执行交易操作，模拟引擎不参与交易执行过程

### 4. 每日快照记录模块

每日快照记录模块记录每个交易日的账户状态（现金、市值、总资产、收益率），为后续分析和报告生成提供数据基础。

**要点：**
- 在每个交易日结束时记录账户快照
- 记录内容包括：日期、现金、市值、总资产、收益、收益率
- 所有快照保存在daily_snapshots列表中
- 快照数据用于后续计算最大回撤、绘制资产曲线等分析

### 5. 报告生成模块

报告生成模块在模拟结束后计算总收益率、最大回撤、交易次数等关键指标，生成完整的性能报告，为评估Agent表现提供数据支持。

**要点：**
- 计算基础指标：初始资金、最终资产、总收益、总收益率、交易天数
- 计算风险指标：最大收益率、最小收益率、最大回撤（通过遍历每日快照计算）
- 统计交易指标：总交易次数、买入次数、卖出次数
- 统计持仓指标：最终持仓明细、各股票收益率
- 生成包含所有指标的报告字典
- 打印格式化的报告到控制台
- 返回完整的报告数据供后续分析使用

## 三、时间循环机制（建议配图3：逐日循环流程图）

模拟引擎采用严格的逐日循环机制，确保时间单向推进且不可回溯，通过标准化的流程控制每个交易日的模拟过程。

**要点：**
- **初始化阶段**：从数据库中获取指定时间范围内的所有交易日列表，过滤掉非交易日（周末、节假日）
- **逐日循环**：对每个交易日执行以下标准流程：
  1. **更新持仓价格**：将所有持仓股票的价格更新为当日收盘价，使账户市值反映真实市场状态
  2. **Agent决策**：调用Agent的决策接口，传入当前日期和账户信息，Agent通过多轮对话和工具调用做出交易决策
     - Agent调用工具层（TradingTools）的工具获取市场数据和账户信息
     - Agent通过工具层执行交易操作（工具层负责验证和执行交易，更新账户状态）
     - Agent返回决策结果（包含success、analysis、reasoning等字段）
  3. **记录快照**：记录每日快照，保存当前账户状态（现金、市值、总资产、收益率）
  4. **记录日志**：将决策和持仓信息记录到日志文件中
- **结束阶段**：当所有交易日完成后，生成最终报告，统计总收益率、最大回撤、交易次数等关键指标

**配图3制作说明**：绘制一个循环流程图，展示"获取交易日列表→逐日循环→更新持仓价格→Agent决策（通过工具层执行交易）→记录快照→下一个交易日"的循环过程，用不同颜色区分各个阶段，并在关键节点标注数据状态。

## 四、数据防泄露机制（建议配图4：时间线示意图）

数据防泄露机制是模拟引擎的核心设计原则，严格确保Agent在任何时刻都只能访问当前日期及之前的历史数据，无法看到未来的价格信息，从而保证模拟测试的公平性和真实性。

**要点：**

- **第一层：时间推进控制**
  - 模拟引擎严格按照交易日顺序逐日推进
  - Agent无法跳过或回溯到未来日期
  - 时间单向流动，不可逆转

- **第二层：数据访问限制**
  - MarketDataProvider在提供数据时严格检查日期
  - 只返回小于等于当前日期的数据
  - 任何尝试访问未来日期的请求都会返回空结果
  - 确保Agent无法通过数据接口获取未来信息

- **第三层：持仓价格更新时机**
  - 引擎在每个交易日开始时更新持仓价格
  - 确保Agent看到的账户状态是基于当日及之前的数据计算得出的
  - 持仓价格反映的是当前日期及之前的历史价格，而非未来价格

- **设计意义**：这种三层防护机制确保了模拟测试的公平性，使得Agent的表现能够真实反映其决策能力，而非依赖于未来信息的"作弊"行为

## 五、性能统计与报告生成（建议配图5：报告指标展示图）

性能统计与报告生成模块在模拟结束后自动生成完整的性能报告，包含多维度的统计指标，为评估Agent表现提供全面的数据支持。

**要点：**

- **基础指标统计**
  - 初始资金、最终资产、总收益、总收益率
  - 交易天数（模拟周期内的交易日数量）
  - 反映整体投资表现

- **风险指标计算**
  - 最大收益率：所有交易日中的最高收益率
  - 最小收益率：所有交易日中的最低收益率
  - 最大回撤：通过遍历每日快照，计算从峰值到谷值的最大跌幅
  - 反映投资风险水平

- **交易统计**
  - 总交易次数：所有买入和卖出操作的总数
  - 买入次数：买入操作的数量
  - 卖出次数：卖出操作的数量
  - 最终持仓明细：模拟结束时的持仓情况（股票代码、名称、数量、收益率）
  - 反映交易活跃度和持仓结构

- **数据保存**
  - 每日快照数据：保存完整的daily_snapshots，可用于绘制资产曲线、收益率曲线、回撤曲线等可视化图表
  - 交易日志：保存完整的trade_log，记录所有交易的详细信息
  - 决策日志：通过DualLogger记录Agent的每日决策和理由
  - 持仓日志：通过DualLogger记录每日账户状态和持仓明细
  - 所有数据保存到日志文件中，为后续深入分析提供数据基础

- **报告输出**
  - 生成包含所有指标的报告字典
  - 打印格式化的报告到控制台，包括基础指标、风险指标、交易统计、最终持仓等
  - 返回完整的报告数据供后续程序化分析使用
