# 公司行动来源绑定与历史投影重建

2026-10-30。按用户最新澄清，本轮目标为**预测、模拟、情景推演**，不要求真实交易资格，不接入下单。用户输入的持仓不是券商托管认证。以下实现及真实来源核验不代表 P0–P5 或智能投顾正式发布完成。

## 公司行动与总收益

`cninfo_actions.py` 保存巨潮分红、配股、股本变动三个端点的原始响应、请求参数、接收时间和内容哈希。仅接受 HTTP 200、成功业务状态、`count == total == len(records)`、完整证券及历史查询范围；计数明确的空配股目录可作为该来源范围内的无配股证据。超时、缺字段、截断或未知行动不会变成空目录。

分红从完整每十股实施方案解析，并与数值列交叉核对；送转股和股本变动日期、数量必须能解释。原始收盘价、前一交易日收盘价、拆股乘数、每新股税前现金股利逐日重算：

`log_total_return = log(split × (raw_close + cash_per_new_share) / previous_raw_close)`。

首日是价格锚，不伪造首个零收益；两个交易所基准必须覆盖完全相同的交易日。请求区间不足、缺原始价或有重复版本即失败，不取交集缩短区间。总收益再投资标签与保留分红现金的财富路径分别核验。

2026-11-06 起，构建及独立验证每一行总收益时，行动目录须覆盖**前次收盘次日至本次收盘日**的全部日历日，且三个目录各自的实际接收时间不得早于覆盖终日上海时间 15:00。例如周五到周一的收益，只有周一的无行动证明不够；若目录显示周日除权，当前日线算法也不把这笔分派挪到周一或忽略它。条件投影同样拒绝遗漏已公告除权日的未来交易日序列。此规则只验证上述来源和收益口径，不重写已存标签或早期验证记录。

覆盖限于 `gross_passive_common_share_cash_bonus_transfer_no_subscription_v1`：普通股被动持有、税前现金及已能解释的送转股语义。配股目录非空、未知股本变动、无法解释的混合行动或股本数量差异仍阻断。**不是所有公司行动类型都已实现**；更不代表认购现金、现金代股、分红税、实际到账可用资金已经认证。不能以该范围替代更广的公司行动合同。

`action_coverage_manifest` 支持多证券和每行不同的历史覆盖证据。每个证券/日期必须恰有一个对应覆盖；全局清单不能掩盖某行的晚到来源。一个新汇总清单不需要假装早于历史标签；其原始行来源仍必须逐项验证。

参考：[AKShare 官方分红接口文档](https://akshare.akfamily.xyz/data/stock/stock_issue.html)、[官方维护的巨潮股本/配股适配代码](https://github.com/akfamily/akshare/blob/main/akshare/stock/stock_share_changes_cninfo.py)。复权价不被替换成已验证的投资者总收益，见 [BaoStock 复权说明](https://www.baostock.com/helpdocs/pdf/BaoStock%E5%A4%8D%E6%9D%83%E5%9B%A0%E5%AD%90%E7%AE%80%E4%BB%8B.pdf)。

## 预测模拟的持仓来源

`simulation_inputs.py` 核对研究结果与原不可变组合快照的现金、持仓和原始行情工件，独立重算总值与权重。结果标为 `user_supplied_simulated_holdings`；`broker_custody_verified=false`、`order_submission_enabled=false`。当前约定为税前买入持有、分红留存、现金名义收益为零，不把未知费率填零来模拟真实交易。

验证器 `quantitative-prerequisites-v5-scoped-simulation` 增加独立 `prediction_simulation` 范围。CLI 与研究任务自动验证默认使用该范围；真实交易资格和可执行调仓优化为 `not_applicable`，不阻断条件预测。联合事件财富校准、原始来源、历史信息可见性和概率门槛保持不变。旧 `release` 范围保留，不将“模拟输入已绑定”兑换为券商事实认证。

## 历史投影重建

独立契约为 `ReconstructionPolicy` / `historical_projection_protocol`。必须明确算法、开发期终点、留出期起止、期限和最低训练量。协议真实创建时间等于工件 `known_at`；生成输出另记 `generated_at` 与历史 `information_cutoff`。

显式算法 `event_ols_var1_conditional_mean_v1` 在每个原点只读取已可见的事件特征前缀，拟合 VAR(1) 条件均值。它不是模型故障后的替代品，也不自动降低原模型。训练不足、秩不足、不稳定或任何原始来源当时不可见均保留失败。未来实际事件/价格不参与投影拟合；测试会改写这些未来值核对训练哈希与投影不变。

未来行动仅从原点已捕获的目录读取已公告方案，条件必须显式为 `announced_actions_only_assume_no_unannounced_actions`。未公告行动不发生是**情景假设**，不是完整观察或已校准概率。今天下载的目录不能通过改日期充当历史快照。

逐折输出分为 development / holdout；未成功折不删除，不选择表现最好的子集。工件数据集为 `reconstructed_origin_projection`，不能传成 `joint_origin_forecast` 原始档案。留出为事后按时间划分，不声称证明研究者此前从未看过该数据。

**同日后续已完成独立条件财富评分、成熟窗口检查、消融及留出统计集成，真实统计验收仍未通过。** 新入口为 `score-historical-reconstruction` / `run-reconstructed-simulation`，验证器升级为 v6；详见 [原始公告与评分运行手册](公告来源与重建评分.md)。重建报告本身不签发统计校准，评分另存独立工件；不能改名复用原始档案的通过证书，事件分支概率与发布资格仍为 false。

## 命令与数据接入

使用 `.tmp/advisory-venv/Scripts/python.exe -m src.stock_app.cli`：

- `acquire-action-coverage --db-path <db> --run-id <id> --symbol 002230 --start 2025-04-28 --end 2026-10-28 --output <json>`：成功项按不可变契约恢复，只重试失败项；失败尝试保留在 `corporate_action_attempts`。
- `build-source-bound-total-returns --db-path <db> --inputs <json> --output <json>`：输入严格包含 `coverage_refs`（证券→覆盖ID）、`price_refs`（原始价ID列表）、`benchmark_refs`（指数→工件ID）、`start`、`end`。
- `build-source-bound-wealth-events --db-path <db> --total-return-panel-ref <id> --event-refs <json数组文件> --output <json>`：每证券/日均需原始事件文档；缺日明细写入失败报告，不补零。
- `reconstruct-historical-projections --db-path <db> --panel-ref <id> --protocol-ref <id> --action-sources <json> --output <json>`：行动来源映射为历史原点序号→证券→`dividend/rights/capital` 三个原始目录ID；逐折及总失败入不可变工件。
- `validate-quantitative-release --db-path <db> --run-id <id> --scope prediction_simulation --output <json>`：检查当前预测模拟范围；`--scope release` 才检查旧发布范围。

接入协议工件时，使用 `ReconstructionPolicy`、`policy_payload` 与 `derived_artifact('historical_projection_protocol', 'historical-projection-protocol-v1', payload, actual_capture_time)`。不能手改原点、已冻结协议或 `known_at`。代码入口见 `src/stock_app/historical_projection.py`，完整来源契约集成夹具见 `tests/test_historical_projection.py`；夹具均为合成数据，不能用于真实验收。
