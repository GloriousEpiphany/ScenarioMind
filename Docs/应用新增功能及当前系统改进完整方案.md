# StockM1 应用新增功能及当前系统改进完整方案

更新日期：2026-07-10  
依据：`Docs/情景推演改进V2.md` 与当前代码逐项审计

## 1. 最终产品目标

StockM1 应成为“证据驱动的投资组合决策支持系统”：自动读取持仓，持续收集真实新闻、公告和财报，识别影响持仓的事件，生成受控的后续假设分支，用确定性量化链完成压力测试，最后给出可以复测和比较的调仓候选，以及来自独立股票候选池的选股观察方案。

系统不替代持牌投资顾问，不承诺收益，不把 Agent 投票当成价格预测。真实资料、模型推导和未来假设必须永久分层。

## 2. 本次严格审计结论

### 2.1 已经实现并可继续使用

- `ScenarioEngine.run()` 已串联持仓、情景解析、外部研究、量化压力测试、金融沙盘、Agent 审查、递归事件树、报告和持久化。
- `ResearchPlannerAgent` 能根据情景、持仓代码和名称生成检索问题；研究结果具有来源、时间、质量分和抓取状态。
- `UncertaintyMinerAgent`、`FutureEventGeneratorAgent`、信息包边界闸门、分支注入与递归汇总已实现，分支明确标记为 `generated_hypothesis`，不写入真实外部证据表。
- 前端已有自动推演入口、阶段进度、Agent 家族说明、未来事件树、调仓候选和持仓观察清单。
- 调仓前后比较走量化引擎，而不是由语言模型编造收益数字。

### 2.2 部分实现，不能按生产完成验收

- 默认政策、公告和财报源多数使用入口页快照。入口可访问不等于抓到了具体新闻、公告或定期报告。本次已加入 `evidence_readiness` 闸门，单纯入口页只能标记为 `source_reachable_only`。
- RSS 能抓具体条目，但默认可用的中文财经新闻源不足，且缺少来源 SLA、限速、重试、熔断和长期可用性监控。
- 文章正文读取、分类和质量评分已存在，但 PDF 财报下载、文本/表格抽取、报告期识别、关键指标标准化和同比环比校验尚未形成完整流水线。
- 多 Agent 主要是同进程确定性组件与审查角色，并非隔离部署的长生命周期服务；缺少任务队列、幂等键、分布式追踪、失败补偿和人工复核工作台。
- 当前“选股方案”实质是对现有持仓进行分类，不是从全 A 股候选池筛选新股票。

### 2.3 本次代码补齐

- 新增可注入的 `MCPResearchFetcher`，宿主可以把任意真实搜索/公告/财报 MCP 工具接入统一研究证据契约。
- MCP 返回内容必须至少包含标题和真实来源 URL；缺少来源时失败关闭，不保存为证据。
- `ScenarioEngine` 新增 `research_sources` 与 `research_mcp_transport` 注入点，MCP 不再只是孤立的底层示例。
- 研究审计新增证据就绪度：区分具体文档、入口页快照和无证据状态。

## 3. 各 Agent 对照 V2 的生产验收

| Agent 家族 | 当前状态 | 生产缺口 | 验收标准 |
|---|---|---|---|
| 研究协调 | 基本实现 | 缺少定时任务、去重策略版本和查询预算监控 | 同一事件可幂等重跑，完整记录计划、预算、耗时和失败原因 |
| 政策/新闻采集 | 部分实现 | 默认具体新闻源不足 | 至少两类独立来源；保存原始 URL、发布时间、抓取时间和内容哈希 |
| 公告/财报采集 | 未完整实现 | 默认只是入口页；没有 PDF 解析与财务指标标准化 | 按股票代码和报告期获取具体公告，解析 PDF，并校验报告期与公司主体 |
| 证据清洗分类 | 基本实现 | 缺少跨源实体消歧与冲突检测 | 同文去重，来源冲突显式展示，不能静默覆盖 |
| 量化压力 | 已实现核心链 | 因子覆盖和历史代理仍有限 | 数字只来自可回放数据快照；缺失数据明确降级 |
| 金融沙盘 | 已实现解释层 | 不是现实交易仿真 | 只解释传导路径，不生成收益数字或伪造主体行为 |
| 后续事件生成 | 已实现 | 模板仍需回测校准 | 自动产生 2-5 个分支，全部标记为假设并受预算限制 |
| 边界审查 | 已实现核心规则 | 缺少独立策略服务和拦截指标 | 对无来源事实、越权数字和买卖指令执行失败关闭 |
| 通俗报告 | 已实现 | 需增加证据覆盖与不确定性首页 | 普通投资者一屏看清结论、证据、风险和下一步 |
| 调仓方案 | 候选已实现 | 方案参数较固定，缺少约束优化 | 纳入风险预算、交易成本、涨跌停、停牌、现金和最小交易单位 |
| 选股方案 | 未实现最终目标 | 只评估现有持仓 | 独立候选池、基本面/事件/风险筛选、组合相关性和可复测入选理由 |

## 4. 真实网络信息接入架构

推荐统一使用 `ResearchSourceConfig -> Collector Agent -> ExternalEvidenceDocument -> Evidence Quality Gate -> scenario_external_evidence`，HTTP、RSS、供应商 API 和 MCP 都只能通过这条链进入系统。

MCP 接入约定：宿主向 `research_mcp_transport(request)` 返回 `documents`；每条至少提供 `title`、`url`，建议提供 `document_type`、`published_at`、`summary`、`content_markdown`、`official`。工具返回的文本不能天然视为可信，仍需经过来源、时间、主体和相关性校验。

生产源优先级：交易所/巨潮具体公告与公司 IR 页面 > 监管和政府网站 > 有许可的财经资讯 API > 可审计 RSS > 热榜。热榜只能用于发现线索，不能单独改变量化结果。

## 5. 新增关键应用功能

### P0：持仓风险雷达与每日行动页

每日自动完成增量采集、持仓事件匹配、财报日历、风险分支推演和组合压力测试。首页只给四项：今天发生了什么、哪些持仓受影响、是否需要复测调仓、需要继续观察什么。每项均可追溯来源。

### P0：生产级公告与财报流水线

按股票代码、公告类型和报告期抓取具体文档；保存原始文件哈希；解析资产负债表、利润表、现金流量表和审计意见；做单位、币种、报告期和同比校验；异常结果进入人工复核队列。

### P0：真正的调仓优化器

把当前固定比例候选升级为约束优化：目标包括降低组合下沿、集中度和事件暴露；约束包括最大单股权重、现金下限、行业上限、交易成本、停牌/涨跌停和最小交易单位。输出防守、均衡、进取三组可复测方案及相对当前组合的变化。

### P0：真正的选股候选池

从本地全 A 股数据和可用财报构建候选池，依次经过数据完整性、流动性、财务质量、估值、事件相关性、风险和组合相关性筛选。输出“为什么入选、支持证据、反证、适配情景、失效条件”，并用同一情景引擎与现有持仓共同压力测试。

### P1：事件驱动观察清单

把假设分支中的观察信号转换为可执行监控规则；真实新闻、公告或财报命中后，只改变分支状态并触发重跑，绝不把假设反写为事实。

### P1：决策复盘与校准

记录当时的数据快照、候选方案和未行动方案，事后比较实际路径。按事件类型校准区间覆盖率、误报率和调仓改善幅度，而不是用单次收益评价 Agent 文本。

## 6. 工程化落地路径

### 第一阶段：真实证据闭环（2-4 周）

接入至少一个具体公告/财报 API 或 MCP、两个新闻/RSS 源；完成 PDF 存档与解析；加入定时采集、幂等、重试、限速、内容哈希、来源健康度和证据覆盖看板。验收时必须用真实股票代码展示具体报告 URL，不接受入口页快照。

### 第二阶段：决策闭环（3-5 周）

实现候选池、财务特征、风险特征、组合相关性、约束调仓优化和交易成本。前端支持当前组合与三组方案一键比较，并说明数据不足项。

### 第三阶段：生产运行（2-4 周）

把采集、解析、推演和报告拆为可重试任务；加入任务队列、租约锁、幂等键、超时、熔断、结构化日志、指标、告警和审计保留策略。敏感配置进入密钥管理，不写数据库和日志。

### 第四阶段：评测与灰度（持续）

建立新闻命中、财报解析、证据引用、假设边界、区间覆盖、调仓改善和候选稳定性数据集。先做只读影子运行，再向少量用户开放候选比较，最后才考虑连接真实交易系统；任何真实下单必须是独立权限域和人工确认。

## 7. 上线硬闸门

- 没有具体来源 URL 的新闻、公告、财报不得进入事实链。
- 只有入口页快照时，界面必须显示“来源可访问，但未取得具体资料”。
- 生成假设不得写入 `scenario_external_evidence`，不得直接改变收益区间。
- 财报主体、报告期或单位校验失败时不得用于选股评分。
- 调仓和选股必须展示数据日期、覆盖率、反证和失效条件。
- 任何 Agent/MCP 超时或失败必须可见并可重试，不能用模型补写缺失事实。
- 未完成真实源、调仓约束优化和独立候选池前，产品状态应标记为“研究与压力测试版”，不能宣称自动投顾已完成。

## 8. 最终判断

当前系统已经具备有价值的“持仓情景压力测试 + 自动后续事件探索 + 可比较调仓候选”核心，适合成为投资研究辅助工具；但尚不能完整达到“自动收集具体新闻和财报、全市场选股、生产级自动调仓建议”的最终目标。最关键的新增路径不是继续增加 Agent 名称，而是完成真实数据文档闭环、独立选股候选池、约束调仓优化和可观测任务运行。完成上述 P0 与上线硬闸门后，系统才具备真正持续应用的关键用途。

## 9. 2026-07-10 阶段实施记录

本轮已经完成并通过自动化验证：

- 巨潮具体公告/年度报告 Adapter：先解析证券主体标识，再按股票代码和报告期查询具体公告，返回 `static.cninfo.com.cn` PDF URL；不再把巨潮首页当作财报。
- MCP 证据 Adapter：标题或来源 URL 缺失时失败关闭。
- 证据就绪度：区分具体文档、仅入口页和无证据，并在前端明确展示。
- PDF 正文读取：完整运行环境安装 `pypdf` 后可抽取文本；无文本或解析失败时明确拒绝。
- 财务事实标准化 Seam：校验股票代码、报告期、报表类型、币种、单位和核心指标；未通过的事实不得写入标准化财报表。
- 决策支持 Module：生成防守、均衡、观察三组目标权重，显示现金目标、估算换手和成本；从持仓外本地行情构建候选池并展示反证和失效条件。
- 生产轮询：增加重叠运行保护、指数退避重试、耗时、失败数和跳过数。
- Module 深化：环境检测合并到能力报告，调仓比较合并到决策支持，研究检索透传层被移除；MCP、RSS、PDF、事件轮询等真实 Adapter/Seam 保持独立。
- UI：增加研究版状态、四步流程、联网状态说明、证据就绪度、持仓外候选池；修复当前 Streamlit 下 `width='stretch'` 导致股票列表页崩溃的问题。

实网验收证据：使用 `000001` 查询得到平安银行年度报告具体 PDF；完整情景链能把它作为 `external_earnings` 证据进入报告。标准化财务指标仍只有在 PDF/MCP 提供可校验结构化数值后才会写入，禁止用标题或语言模型补造。

仍需外部条件才能完成的上线项：有许可的第二新闻源、财务指标供应商或稳定抽取规则、实时停牌/涨跌停与行业数据、任务队列的多进程部署、密钥管理、告警通道以及灰度用户。上述项目没有外部数据授权和部署环境时不能用本地占位代码冒充生产验收完成。
