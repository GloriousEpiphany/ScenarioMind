# 持仓自动情景研究

入口为情景推演页面或 `portfolio-analysis` CLI。录入持仓、配置推理模型后，系统自动采集持仓日线、财务报告、行业归属、个股新闻与文本特征、资金流及沪深指数市场背景。普通新任务将新闻联播作为附加来源；明确勾选完整节目分析时才要求整期完整。多个有持仓账户时，先明确选择账户。

## Agent 结构与推演算法

新任务默认进入 `ResearchController`：总控制定并修订结构化研究计划，选择满足依赖的任务；宏观、公司、情绪独立完成后合成情景，量化 Agent 执行并审查数值工具，组合 Agent 读取情景和量化结果，最后登记跟踪。每个研究角色使用持久化 AgentRuntime，有独立 critic；服务端检查任务完成、实验覆盖、证据读取和预算，模型不能跳过这些检查。旧 `PortfolioResearch` 保留供旧契约和报告修订兼容，不将旧报告冒充新总控报告。

量化输入在研究截止时点冻结之前采集：东方财富原始日线/双交易所基准、巨潮公司行动、逐行来源绑定的共同收益面板。无法获得完整数据时保存具体阻断。模型只能向 `estimate_exposure`、`simulate_paths`、`optimize_portfolio`、`validate_proposal` 提交注册实验 ID，不能提交收益数组、概率或阈值。拟合与同步抽样路径是实际计算，但默认零额外冲击的总收益路径不是现金股息持仓路径认证，更不是语义事件概率校准。

模拟输出的 1/5/20/60 表示交易步数，分位水平为 10%/50%/90%。新输出显式包含 `horizon_unit` 和 `quantile_levels`；旧缓存按同一统计定义解释，不改写原结果。量化独立审查区分条件研究完整性与数值发布资格：实际工具返回的 `blocked` 可以是完整研究必须报告的结论，不能要求反复调用相同工具来制造通过。`review-scope-amendment` 留存范围澄清，旧决定按原输入重放，预算和发布门槛不变。

报告通过总控审查后自动登记并启动后台跟踪。新证据或每 24 小时复核进入持久化反馈队列，最多登记 3 次。默认后台只入队，不执行新的模型复核；需显式运行 `--execute-feedback` 才执行。每次跟进是新任务，模型/工具上限数值继承父任务，但不是共享父任务剩余额度，因此会产生额外 API 用量。子任务不再创建跟踪链。跟进重新冻结持仓与原件，强制情景和组合专家读取触发证据；旧报告、旧原点和旧预算记录不改写。预算耗尽是未完成，不以跳过审查换取成功。

进程退出后可恢复同一数据库，已经完成的任务不重复执行。Windows 后台进程不打开控制台，日志在数据库同级 `portfolio-research-logs/tracking-worker.log`。机器关机期间不能采集或发出预测；重启后使用以下命令恢复，不能补发停机期间的历史原点：

```powershell
.tmp/advisory-venv/Scripts/python.exe -m src.stock_app.cli research-monitor-worker --db-path 数据库路径 --execute-feedback
```

仅检查一次用 `--once`；不加 `--execute-feedback` 时只生成待处理研究任务，不调用模型。前瞻发行人研究可用 `register-forward-watch --db-path … --symbol 002230 --market-start 2025-04-28 --event-start 2025-04-28` 登记并启动，日期必须是研究预先声明的真实历史边界，不要求从上市年份开始。工作器在上海时间 15:30 后核对双交易所实际收盘，再发当天原点；缺当天行情时最多 3 次使用新请求重试，不能被首次不完整缓存永久锁死。

到期审计与发预测分开运行，即使当天是周末或尚未收盘，也可根据已经实际结束的交易日和完整公告日期审计已有原点。每日最多 3 次，成功后重复执行不再入账；不拿星期数推断成熟，不改变旧评价协议，也不补发过去原点。

有新官方原件时，先生成独立论点复核，再尝试需要最新市场资料的完整研究。完整 PDF 已保存，复核围绕报告期与具体论点检索、读取相关原文及反证；机器检查每条更新的精确引用确实出现在已读片段中。局部阅读不得声称全文审阅。该阶段不能用历史年报更新当前估值或调仓建议，和后续任务共用原全局预算；完整市场资料失败仍保持 `data_incomplete`，不会被论点复核成功覆盖。

版本化算法依次执行事实核对、现金流/贴现率/资产负债表传导、替代解释与已计价核查、相互强化/抵消的情景分叉、逐仓风险映射、不交易对照、条件操作与现金/直接减仓对冲、独立反证。每个情景保留父路径、原始证据、触发与失效条件。

模型输入只包含分析所需的证券代码、数量、成本、现金/总值、权重、行情证据引用、投资偏好和公开资料，不包含账户名、账户标识或 API 密钥。首次启用前应确认向所配置模型服务发送持仓信息的授权；本次获准的一次 DeepSeek 复核不构成任意后续任务的无限授权。

## 执行与恢复

隔离解释器：`.tmp/advisory-venv/Scripts/python.exe`。默认系统 Python 3.14 缺少项目依赖。

`DataUnavailable` 与 `RuntimeUnavailable` 分开处理：前者表示事实输入不可用，后者表示当前解释器的研究依赖缺失或不兼容。实际导入检查覆盖 LangGraph、SQLite saver、LangSmith tracing API 和 OpenAI client，在新任务创建、worker 启动和研究采集之前完成。不能仅通过 `find_spec('langgraph')` 判断环境可运行。

若出现 `runtime_unavailable`，查看 `diagnostics.component`、`python_executable` 和 `requirements_file`。在该解释器安装锁定依赖，或使用上述已配置解释器启动页面，再恢复原 ID。环境修复不修改冻结模型、来源、预算和已采集输入。未知请求版本明确拒绝，不能落入旧执行器；恢复时不允许用 `--require-cctv` 暗中修改来源范围。

错误记录始终包含执行阶段。报告已经完成但后续验证或跟踪启动失败时，保留报告和后续错误，不抹掉已完成结果；数值发布资格仍由独立验证决定。

```powershell
.\.tmp\advisory-venv\Scripts\python.exe -m src.stock_app.cli portfolio-analysis `
  --db-path data/stock_data.db --account-id 2 --output .tmp/portfolio-report.json
```

只有一个有持仓账户时可以省略 `--account-id`。来源使用配置中的明确选择，可在新任务创建时通过 `--price-source eastmoney_http` 指定。恢复只传原任务 ID：

```powershell
.\.tmp\advisory-venv\Scripts\python.exe -m src.stock_app.cli portfolio-analysis `
  --db-path data/stock_data.db --run-id 'portfolio:原任务ID' --output .tmp/portfolio-report.json
```

任务请求冻结模型、端点哈希、工具/提示词版本、投资偏好、来源、日期、新闻联播期次及总预算。成功采集和通过审查的角色不重复执行；改变冻结参数须创建新任务。持仓在下载期间变化会拒绝继续，不发布旧账户分析。

模型若无视单调用参数而返回一批工具调用，研究总控、专家与量化运行时拒绝整个响应，保存协议纠错记录并要求单步重试。被拒绝批次不执行，失败尝试仍计入原预算。恢复 v3 运行时只在其余合同字段完全一致时追加 `protocol-repair-amendment`；原合同、提示词、输入、已通过结果和调用次数不改写。新运行使用 v4 协议纠错契约。

工具参数不是合法有限 JSON 时同样保存安全错误类别并要求模型纠正，不执行该调用、不保存提供方原始响应。旧检查点通过 `tool-arguments-repair-amendment` 记录这一协议修复；未知工具、模型不匹配与其他合同错误仍明确拒绝。

`request_review` 先执行原有的确定性证据检查，补齐必读页、已引用原文、任务和计算后才调用独立 critic。未满足时返回缺口与 `next_required_reads`，不消耗 critic 调用；阅读不连续时从首个未覆盖页继续。机器拒绝保存为 `review-preflight:*`，不冒充模型审查。`review-preflight-amendment` 记录该调度修复，证据标准和原预算保持不变；独立审查返回后仍复验同一组门槛。

`propose_hypotheses` 每次提交完整的当前候选集合，后一次提交替换前一次候选，并非追加一条路径。旧候选仅留作审计，不能与修订稿自动拼接；独立审查及报告只取最近一次成功提交。

总控计划的停止条件必须恰好是三个注册条件。多写或漏写时返回可纠正的参数拒绝，计划不落账；纠正后的计划仍检查完整职责和固定依赖，不允许模型自定义完成标准。

同账户的后台任务串行执行。连续编辑偏好会合并尚未执行的旧请求，已运行研究与证据保留；后台 worker 完成当前任务后自动处理最新排队项。报告完成或失败后停止前端定时轮询。

新任务调用预算可通过 `--max-model-calls`、`--max-tool-calls` 明确设置，默认全队 144/112。参数拒绝与失败尝试同样受预算控制；不能通过恢复调高旧预算。页面只在预算耗尽后显示新任务预算设置。

最终语义复核发现错误时，旧成功报告保留但不作为当前交付。修订复用冻结证据与已通过角色，在原剩余额度内重审情景/持仓；若原额度已尽，必须有明确的单独续办授权，绑定新额度、原报告哈希及已通过情景。续办授权不可用于不同契约，旧预算不改。研究者恰好完成候选后若份额用完，可把候选交给已预留的独立审查容量；保留原停止记录，仍由同一全局预算计数，不跳过审查。

后续专家及其独立审查可复用已通过专家的精确只读查询缓存，前提是证据截止、冻结清单哈希、组合上下文、工具描述/版本和完整请求哈希均一致。只复用原始证据页，不复用对方的推理或审查结论。源运行与结果哈希逐条保存；缓存命中不发生新工具读，选择查询的模型调用仍计入预算，新查询照常受原上限约束。

量化输入在冻结前按请求中的 `max_task_attempts` 重试失败来源，继续使用原采集 ID 和成功检查点；不会因为一次连接错误立即冻结空实验。面板校验失败不靠重复联网解决，重试耗尽仍如实记录阻断。已冻结的失败输入不被后来取得的数据覆盖；如需重新冻结，必须保留旧请求，并在既有授权额度内扣除已消耗调用。

每个采集组件最多进行三次相同来源/协议/参数的尝试，失败保存在 `acquisition_attempts`。东方财富每个已成功解析、验证的区间请求单独保存不可变检查点；后续请求失败无需重新下载此前区间。失败不会换源、换模型、放弃基准覆盖或填补行情。缓存仅在同一运行契约下复用。

真实执行事件写入 `portfolio_research_events`，不按计时器制造进度。前端只轮询账本；独立 worker 不依赖网页连接。任务状态、结果、异常类型分别保存于 `portfolio_research_jobs`。调用前持久化预留全队模型/工具预算；失败调用也计入，预算耗尽不能跳过审查或调高原预算。

原数据库中旧来源行情不会与新任务混用。采集按冻结 SourcePlan 过滤来源，组合估值只读取明确来源及冻结价格工件 ID；后到修订或其他来源不能替换本轮估值。未明确来源的旧入口仍保留冲突拒绝。

模型 HTTP 402 等错误明确停止并保存；恢复不重复已通过角色。新增错误追加表保留恢复前的异常记录，不记录提供方原始响应或密钥。[DeepSeek 官方错误码](https://api-docs.deepseek.com/quick_start/error_codes/)将 402 定义为余额不足；补充由用户操作，程序不代充值、不自动更换模型。

## 来源与网络

新闻联播使用央视官方 `https://tv.cctv.com/lm/xwlb/day/YYYYMMDD.shtml` 及各条目的原始 HTTPS 页面，不使用第三方转录站。逐条检查原文结构，任一稿件失败即拒绝整期；发布时点精度明确为保守的整期时间，而非伪造精确文章发布时间。当天稿件默认在北京时间 21:00 后选用，此前选上一期。

市场背景按上证与深证的相同交易日读取指数原始日线，计算已观察的 5/20 个交易日收益。它们不是投资者情绪调查或未来收益率。个股文本词典分数同样明确是文本派生特征，不代表全市场投资者观点。

2026-10-28 真实对照确认：当前全局代理路径下央视 HTTPS 握手失败，限域直连返回 200。用户随后明确授权仅 `cctv.com`、`cntv.cn` 持久直连。客户端切换为规则模式，前置两条央视 DIRECT 和 `MATCH,GLOBAL`，其余流量保持原 GLOBAL 选择。原规则保留在前置项之后；配置备份位于用户 Clash Verge 配置目录内的 `stockm1-cctv-backup-20261028`。全局扩展脚本与持久模式均保存，证明见 `.tmp/cctv-persistent-route-proof-1028.json`。禁止将配置内凭据复制进仓库或日志。

## 输出验收边界

`conditional_research_complete` 只表示完整条件研究与五个角色的独立审查通过。报告包含综合判断、逐仓影响、条件操作、现金/减仓对冲、成本与剩余风险、不交易对照、观察信号及证据/拒绝记录。

它不代表正式量化交易发布已通过。联合路径校准、多期优化与交易资格仍由原严格内核控制；未通过时保持 `publication_eligible=false`、`numeric_impact_status=not_estimated`、`probability_status=uncalibrated`。不生成模型臆测的收益、概率、目标价或交易数量。前端明确展示该状态，并保留高级量化研究控制台。

外部依据：[LangGraph 工作流与 Agent](https://docs.langchain.com/oss/python/langgraph/workflows-agents)、[央视新闻联播栏目](https://tv.cctv.com/lm/xwlb/)、[Clash Verge 扩展配置与应用优先级](https://www.clashverge.dev/guide/extend.html)。具体集成同样核对了本机锁定 AKShare 的 `news_cctv`、指数日线、巨潮行业与公司资料实现。

## 来源范围与版本兼容

普通新任务将 CCTV 作为附加来源；失败不提交半份节目，而是保存 evidence_gaps，限制相关事实断言。宏观专家仍必须读取双交易所基准和持仓财务/行业证据，行情涨跌不能单独证明政策或机制。缺口进入冻结输入、专家上下文、报告和页面。

需要完整节目分析时，在页面“投资偏好与研究目标”勾选相应选项，或新 CLI 任务加 --require-cctv。旧请求未声明 cctv_required 的，仍按完整节目合同运行。恢复旧任务不改变提示词或来源策略；修改研究范围须新请求。自动跟踪继承原请求的范围。

自动工作器先执行到期审计与真实交易日签发，再处理模型反馈。真实复核与外部数据结果统一见[当前进度](量化研究实现进度.md)。

旧 v1 未完成组合执行协议已退休，返回 requires_new_request，不再提供无效重试；需按当前目标创建新任务。旧证据、预算、已完成报告和可恢复的 v2 合同不改写。
